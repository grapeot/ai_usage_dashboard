# E1002 Local Dashboard RFC

## Architecture

```text
AI usage aggregation
  -> local FastAPI service
  -> E1002 HTTP client
  -> native e-ink rendering
```

The Python layer computes. The service layer exposes a stable local contract. The device layer renders and handles buttons, wake scheduling, and fallback display behavior.

## API

The local service exposes:

```text
GET  /health
GET  /token_usage.json
POST /api/v1/display/update
```

`POST /api/v1/display/update` accepts:

```json
{
  "reason": "force_button",
  "view": "7d",
  "device_id": "example-device"
}
```

The response reuses the dashboard JSON contract generated by `auto_usage.py`.

## Configuration

Public firmware includes only placeholders. Private deployment values live in `eink/e1002/secrets.h`:

- Wi-Fi SSID and password
- update URL
- cached JSON URL
- device id

The public template is `eink/e1002/secrets.h.example`.

## Button Semantics

- Green button: force update through `POST /api/v1/display/update`.
- White button: switch view mode locally, without network fetch.
- Timer wake: fetch only during the configured update window.

## Error Handling

If update fails, the device should fall back in this order:

1. cached GET response
2. last-good in-memory payload
3. visible error state

The service should prefer returning a valid stale payload over returning an empty response.

## Validation

- Python tests cover service contract and mirrored pure firmware logic.
- Arduino compile checks cover sketch integrity.
- Manual hardware smoke tests cover wake, network, rendering, and button behavior.
